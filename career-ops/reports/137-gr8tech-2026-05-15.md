## F: Interview Prep (STAR+R Stories)

**1. "Describe an ETL pipeline you built for high-volume data"**
> UMPSA: ingested daily hostel management data (attendance, payments, maintenance) from multiple input sources (manual Excel + web forms). Built Python transformation layer, loaded into structured DB, surfaced in Power BI. Reduced 5h manual work → 30min automated run.

**2. "How do you handle data pipeline failures in production?"**
> Mercedes-Benz escalation system: when Power Automate flow failed (network timeout), escalations were lost. Built retry logic + email alert to admin on failure. Added status dashboard so Ops team could see pipeline health in real-time. Zero missed escalations after fix.

**3. "What's your experience with Python for data engineering?"**
> Python/Pandas for data transformation in Moinfinity client pipelines. Azure Databricks cert includes PySpark for large-scale batch processing. Currently building personal pipelines using Python + DuckDB to deepen SQL + orchestration skills.

**4. "Tell me about a project with significant data volume or complexity"**
> Mercedes-Benz: attendance data for 500+ employees across 6-month rolling window. Complex DAX measures for shift patterns, overtime calculation, absence tracking. Optimized data model to handle real-time updates without performance degradation.

**5. "How do you learn a new technology under deadline?"**
> Moinfinity Australian client: needed Shopify API integration I'd never built before. 3 days of documentation study + sandbox testing. Delivered working integration within 1 week. Consistently use "read → build toy example → apply to real project" learning framework.

**6. "Describe working in a distributed/remote team"**
> Moinfinity: all 7 clients were remote (US, Australia, Malaysia). Managed all communication async (Slack + Loom video updates), delivered on time for all engagements. No time-zone-related delays through disciplined async communication.

**7. "Why data platform vs. product analytics?"**
> Data platform engineering is leverage work — building the infrastructure that enables every analyst and business team to do their best work. I prefer owning the foundation that everything else rests on.
