## F: Interview Prep (STAR+R Stories)

**1. "Describe a production data pipeline you built and operated"**
> UMPSA hostel system: production pipeline ingesting multi-source data daily (web forms + Excel uploads), transformation layer in Python, load into PostgreSQL-equivalent DB, surfaced in Power BI. Operated for 13+ months with 30-min daily runtime. No missed runs.

**2. "How do you approach data quality at scale?"**
> UMPSA: implemented validation rules at ingestion (null checks, type validation, duplicate detection). Built alerting for anomalous records. Created data quality dashboard showing pass/fail rates. Zero data quality incidents in production for the full 13-month operation period.

**3. "Tell me about a time you had to process large volumes of data efficiently"**
> Azure Databricks cert: studied patterns for processing TB-scale datasets using Delta Lake and PySpark. Applied partitioning strategies (date/category partitioning), Z-ordering for query optimization, and caching for repeated transforms.

**4. "How do you handle high-availability requirements for a data ingestion service?"**
> Theoretical/cert knowledge: At Databricks-cert level studied patterns for fault-tolerant ingestion (checkpointing, idempotent writes, dead-letter queues). Would apply: checkpoint every batch, retry with exponential backoff, dead-letter queue for poison records, monitoring with alerting.

**5. "Describe a streaming data challenge"**
> Not personal experience — honest gap. Would frame: "My batch pipeline experience gives me the foundation; I'm actively learning Kafka through personal projects and see streaming as the natural next step from the batch pipelines I've built."

**6. "Why e-commerce / why Constructor?"**
> E-commerce search generates some of the highest-volume, highest-stakes real-time data in tech — every search request is a potential revenue event. Building the data lake that powers that system is working at the intersection of infrastructure engineering and business impact. That's exactly the kind of challenge I want.

**7. "How do you work in a fully distributed team?"**
> Moinfinity: all 7 clients were remote across 3 time zones. Managed all communication async — Loom updates, documented decisions in Notion, asynchronous code review via GitHub. Zero coordination failures across 3 years of remote-only operation.
